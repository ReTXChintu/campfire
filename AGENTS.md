# Campfire — monorepo

`apps/frontend` (Vite + React SPA) and `apps/backend` (Express + TypeScript, compiled to `dist/` and run with plain `node`, no framework magic) are npm workspaces. `apps/mobile` (Flutter, Android/iOS) is a separate app in the same monorepo but is **not** an npm workspace (Flutter has its own toolchain/`pubspec.yaml`) — it has **no admin screens at all**, by design; admin/curation only exists on the web.

- Root scripts (`npm run dev` / `build` / `lint`) fan out to the two npm workspaces — see root `package.json`. Mobile has its own `flutter` commands (see `apps/mobile/README.md`), plus `npm run mobile:analyze` / `mobile:build:web` convenience wrappers.
- `release-it` runs from the repo root only; it bumps root + both `apps/*/package.json` (via `npm version --workspaces`) *and* `apps/mobile/pubspec.yaml` (via `scripts/sync-mobile-version.mjs`, since that's not an npm package) together in one commit/tag (see `.release-it.json`'s `after:bump` hook).
- **No OAuth** — plain email/password (bcrypt). One admin account is seeded into Mongo from `ADMIN_EMAIL`/`ADMIN_PASSWORD` (`apps/backend/.env`) on every startup (`lib/users.ts`'s `seedAdminUser`, called from `index.ts`); everyone else signs up via `POST /auth/signup` (`lib/users.ts`'s `createUser`, open — no invite code), which never grants admin (`isAdminEmail()` only ever matches the one seeded email). `POST /auth/login` and `/auth/signup` are the only ways in, on web and mobile alike. Auth is a self-issued JWT, sent as `Authorization: Bearer` — not cookies, since frontend/backend/mobile are all cross-origin from the backend in production. Web `<video>`/`<img>` tags that can't set that header use a separately-scoped, short-lived media token instead (`GET /api/media-token`; see `apps/backend/src/middleware/mediaAuth.ts`). Mobile uses the same media token for video/subtitle streams (Flutter Web's `<video>` has the identical header limitation as a browser; native Android/iOS *can* set headers but the token path is used everywhere for one consistent code path) but plain Bearer headers for images (`Image.network` supports custom headers on every Flutter platform, unlike `<img>`).
- The backend is the only thing that touches `ffmpeg`/Google Drive; it needs a persistent process (VPS), not a serverless function — that's the whole reason this was split out of the previous single Next.js app.
- Deployment can also be pm2 on a single VPS over `https://<IP>:<PORT>` (no domain/reverse proxy) — root `ecosystem.config.js` reads the root `.env` (ports, TLS cert paths; separate from each app's own `.env`) and starts both apps; `scripts/generate-self-signed-cert.sh` makes the cert. Both `apps/backend/src/index.ts` and `apps/frontend/serve.mjs` fall back to plain HTTP when `SSL_CERT_PATH`/`SSL_KEY_PATH` aren't set (local dev). See the root README's "Deployment" section.
