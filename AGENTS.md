# Campfire — monorepo

`apps/frontend` (Vite + React SPA) and `apps/backend` (Express + TypeScript, compiled to `dist/` and run with plain `node`, no framework magic) are npm workspaces. `apps/mobile` (Flutter, Android/iOS) is a separate app in the same monorepo but is **not** an npm workspace (Flutter has its own toolchain/`pubspec.yaml`) — it has **no admin screens at all**, by design; admin/curation only exists on the web.

- Root scripts (`npm run dev` / `build` / `lint`) fan out to the two npm workspaces — see root `package.json`. Mobile has its own `flutter` commands (see `apps/mobile/README.md`), plus `npm run mobile:analyze` / `mobile:build:web` convenience wrappers.
- `release-it` runs from the repo root only; it bumps root + both `apps/*/package.json` (via `npm version --workspaces`) *and* `apps/mobile/pubspec.yaml` (via `scripts/sync-mobile-version.mjs`, since that's not an npm package) together in one commit/tag (see `.release-it.json`'s `after:bump` hook).
- Auth is Passport (Google OAuth) + a self-issued JWT, sent as `Authorization: Bearer` — not cookies, since frontend/backend/mobile are all cross-origin from the backend in production. Web `<video>`/`<img>` tags that can't set that header use a separately-scoped, short-lived media token instead (`GET /api/media-token`; see `apps/backend/src/middleware/mediaAuth.ts`). Mobile uses the same media token for video/subtitle streams (Flutter Web's `<video>` has the identical header limitation as a browser; native Android/iOS *can* set headers but the token path is used everywhere for one consistent code path) but plain Bearer headers for images (`Image.network` supports custom headers on every Flutter platform, unlike `<img>`). Mobile signs in natively via `google_sign_in` and exchanges the Google ID token for the same JWT via `POST /auth/google/mobile`, not the browser-redirect OAuth flow the web app uses.
- The backend is the only thing that touches `ffmpeg`/Google Drive; it needs a persistent process (VPS), not a serverless function — that's the whole reason this was split out of the previous single Next.js app.
